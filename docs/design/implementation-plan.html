Arto / interface — 実装計画

決まった仕様を、
6段に分けて入れます。

各段は単独で動く状態に着地します ―― 途中で止めても壊れません。 先に純粋なロジックを置き、UI はその上に載せ、古いものは受け皿ができてから外す、という順です。

対象 — crates/arto, crates/arto-config, frontend 段 — 0 から 5 関門 — just fmt check test

前提

3つの原則が、順番を決めています

ロジックを先に。根の判定と履歴のまとめ方は純粋関数なので、UI より先に書けてテストも書けます。 表示を差し替える段では、動くと分かっているものを繋ぐだけになります。

受け皿ができてから外す。タブバー・右サイドバー・ピン留めチップは、代わりが動いてから消します。 削除だけの段（第4段）を独立させたのはそのためです。

各段で just fmt check test が通る。 中間状態でも起動して読める、を保ちます。アプリの起動は各段の終わりに手元で確認してください （.claude/CLAUDE.md のとおり、こちらからは起動しません）。

段入るもの外れるもの規模
0 — 静かなクローム不透明度トークン、16px グリフ、設定ウィンドウホバートリガー、設定タブ小
1 — データモデルroots.rs、visits.rs、場所の導出—中（UI 変化なし）
2 — レールと Files 面レール、3状態、複数根、目次ガター右サイドバー大

5 — 幅への応答と設定最小幅と譲り順、設定画面の更新、⌘N / ⌘⇧N—中

Phase 1 データモデル UI は変わらない

根の判定と履歴を純粋なロジックとして置き、テストで固めます。この段では既存の UI から使いません ―― 先に正しさを確定させるのが目的です。

crates/arto/src/roots.rs 新規

pub struct Roots {
    /// Permanent, shared across windows. Derived from directory bookmarks.
    places: Vec<PathBuf>,
    /// This window only, most recently touched last. Capped at MAX_TEMPS.
    temps: Vec<TempRoot>,
}

pub enum Origin { Implicit, Explicit }

pub enum Decision {
    /// Already covered — reveal the path inside this root.
    Reveal { root: PathBuf },
    /// Not covered — push this directory as a temporary root.
    Push { root: PathBuf, absorbed: Vec<PathBuf> },
}

impl Roots {
    /// The whole rule, in one place. See the spec's decision table.
    pub fn decide(&self, target: &Path, origin: Origin) -> Decision;
    pub fn apply(&mut self, decision: &Decision);
}

/// Walk up to the nearest VCS directory; fall back to the parent, and
/// refuse a root as broad as $HOME or a volume root.
pub fn start_root_for(file: &Path, home: &Path) -> PathBuf;

/// Normalise before any comparison: fold `..`, resolve symlinks, and
/// case-fold on macOS. Two spellings of one directory must not stack.
pub fn canonical_key(path: &Path) -> PathBuf;

crates/arto/src/visits.rs 新規

pub struct Visit { pub path: PathBuf, pub at: SystemTime }

pub enum Bucket { Today, Yesterday, ThisWeek, LastWeek, Month(i32, u32), Year(i32) }

/// Newest first, coarsening with age. Buckets never overlap.
pub fn group(visits: &[Visit], now: SystemTime) -> Vec<(Bucket, Vec<&Visit>)>;

/// Saved to visits.json beside bookmarks.json, capped at 5,000 entries.
/// Same shape as BOOKMARKS: a LazyLock<RwLock<_>> plus a broadcast.
pub static VISITS: LazyLock<RwLock<Visits>>;
pub static VISITS_CHANGED: LazyLock<broadcast::Sender<()>>;

既存への追加

  • bookmarks.rs に Bookmarks::places()ディレクトリのブックマークだけを返す。場所の実体はこれで、新しい保存先は作りません
  • state/persistence.rs の PersistedState に temps: Vec<PathBuf>旧 directory: Option<PathBuf> は #[serde(default)] のまま残し、読み込み時に temps へ移す。session.json の後方互換

テスト

  • roots::tests — 仕様の判定表をそのまま表駆動でtempfile で .git のあるツリーと無いツリーを作り、暗黙／明示 × 含む／含まない の4通り＋入れ子3通り
  • roots::tests::start_root_stops_at_home~ やボリューム根に着地したら親へ戻すこと
  • roots::tests::canonical_key_folds_case_on_macos#[cfg(target_os = "macos")] で分岐
  • visits::tests::group_boundaries境界（今日／昨日／今週／先週／月／年）が重ならないこと。固定の now を渡す純粋関数なので時刻に依存しません
  • visits::tests::cap_drops_oldest
  • 仕様の「手順で追う」6ステップをそのまま1本の統合テストに計画と実装が同じ例で検証されるので、あとから読んでも対応が取れます

完了条件

  • cargo test -p arto が新テストごと通る
  • アプリの見た目と挙動は Phase 0 のまま（配線していないので当然）
  • 古い session.json を読んでも落ちない

Phase 5 幅への応答と設定 仕上げ

狭いときの譲り順を入れ、設定画面を新しい形に合わせます。⌘N と ⌘⇧N を分けます。

譲り順

// crates/arto/src/hooks/layout_budget.rs — 新規
/// Give way from the outside in until the document keeps `min_content`.
/// Returns what may be drawn at this width; state only, never settings.
pub fn budget(effective_width: f64, min_content: f64, panel_w: f64) -> Visible;

pub struct Visible { trace: bool, panel: bool, gutter: bool, rail: bool }

純粋関数なので、仕様の閾値表をそのままテストにできます （640 で 1068 / 930 / 704 / 680、800 で 1228 / 1090 / 864 / 840）。 実効幅はズーム適用後、パネル幅は現在値を渡します。

config.json の差分

{
  "sidebar": {
+   "minContentWidth": 640,
+   "recentTrace": "hidden_when_sidebar",  // never | hidden_when_sidebar
+   "recentTraceCount": 6,                 // | hidden_when_full_width | always
    "defaultShowAllFiles": false,          // 画面から設定へ移動
    ..
  },
  "directory": {
-   "defaultDirectory": "~/notes",         // 起動時に places へ移して削除
    "onStartup": "last_closed",            // 「前回の状態を復元」
-   "onNewWindow": "last_focused"          // ⌘N / ⌘⇧N に置き換え
  },
- "rightSidebar": { .. }                   // 読み飛ばす
}

ウィンドウ

  • ⌘N ＝ 場所だけを引き継いでライブラリで開く既存の window.new の行き先を変えるだけ
  • ⌘⇧N ＝ 複製。一時の根・読んでいる文書・スクロール位置を引き継ぐwindow.duplicate を新設。NewWindowBehavior は不要になるので撤去
  • 起動時は StartupBehavior をそのまま使う既にある仕組みなので、PersistedState に temps が入れば動きます

設定画面

  • preferences_view/tabs/sidebar_tab.rs に痕跡の4択（option-cards）と最小幅（slider）既存の form_controls がそのまま使えます
  • right_sidebar_tab.rs を削除、directory_tab.rs を場所の一覧に

完了条件

  • 窓を縮めると痕跡 → パネル → ガター → レールの順に消え、広げると戻る
  • ⌘B で自分で畳んだ場合は、広げても畳んだまま
  • 痕跡の4択が仕様の表どおりに効く
  • 最小幅を 800 にすると、パネルが 1090px で畳まれる

危ないところ

先に見ておきたい4つ

リスク中身先手
watcher の張り直し 根が増減するたびに FILE_WATCHER を作り直すと、木の再マウントが多発します 根の集合をキーにした use_memo で、集合が変わったときだけ張り直す
パスの正規化 macOS は既定で大文字小文字を区別しません。揃えないと同じ場所が二重に積まれます Phase 1 の canonical_key を単一の入口にし、比較は必ずここを通す
Phase 2 の規模 サイドバーと右サイドバーと目次が同時に動くので、一番大きい段です 「レールと3状態」「複数根」「目次ガター」の3コミットに割る。各コミットで起動できる状態を保つ
30% の読みやすさ high contrast テーマや外光の下で、静止時のグリフが見えない可能性があります Phase 0 で実機確認。[data-theme*="high_contrast"] では1段上げる分岐を用意しておく

着手
