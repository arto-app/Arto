A を土台に B の ⌘K を載せ、C のライブラリを起動画面と新規タブに据える ―― その前提で、 レールは残します。見えている取っ手だからホバーで開いても誤爆しない、という指摘のとおりです。 そして「開いている」という状態そのものを持たず、履歴に集約します ―― その出し方を4パターン並べました。

確定した構成

3案は、こう1つに畳まれます

案 A より 常設は左1枚

複数ルートのツリーとお気に入り。レールで切り替える1面だけです。タブバーと右サイドバーは廃止。

案 B より ⌘K がひとつの入口

移動もコマンドも ⌘K に集約。パネルを閉じていても、これだけで全部に届きます。

案 C より ライブラリが起動画面

起動時と新規タブ（⌘T）で開く画面。お気に入りと最近読んだものが一等地に出ます。

争点

レールが強かったのは、レールだからではありません

強く見えていたのは 20px のアイコン・塗りつぶしのチップ・44px の面という描き方のほうで、 レールという構造そのものではありませんでした。レールには、他では代えられない役割があります ―― 常に見えている、パネルのための取っ手です。

画面端のホバーが誤爆したのは、そこに何も無いからでした。40px の帯が「パネルはここにある」と示していれば、 ポインタがそこへ行くのは意図です。不可視のトリガーを可視の対象に変える ―― これが誤爆への正しい答えで、 トリガーを消すことではありませんでした。前回の私の判断は、そこを取り違えていました。

レールは3つに減ります

Files / Recent / Starred、 それに一番下の設定。⌘1–⌘3 で切り替えます。 Open は入りません ―― 次の節のとおり、その状態自体を持たないからです。

地の扱いはパネルが出ているかどうかだけで決まります ―― 出ていればパネルと同じ地をまとって1枚に見え、 畳めば地を手放して本文の余白に戻る。レール自身の色というものは持ちません。

決定

「開いている」という状態を、持ちません

Arto は読むためのアプリで、未保存の状態がありません。エディタで「開いている」が意味を持つのは、 閉じると失うものがあるからです。失うものが無い場所では、「開いている」と「最近見た」の差は ―― 意図して残したかどうか、それだけになります。そしてその「意図して残す」は、既にお気に入りが担っています。

つまり Open は、タブという器があったから必要に見えていた状態でした。 器を外せば、残るのは履歴（Recent）とお気に入り（Starred）の2つだけです。

検討した案持つ状態「閉じる」は判断
パネルに Open の一覧を常設開いている集合 ＋ 履歴明示的に閉じる見送り ―― タブの器を縦にしただけ
履歴の中に「留め」を持つ履歴 ＋ その中の留め留めを外す見送り ―― お気に入りと役割が重なる
履歴だけを持つ履歴のみ存在しない採用

「閉じる」という操作が消えます。12本溜まるという状態も、原理的に起きません ―― 履歴は勝手に流れるもので、管理する対象ではないからです。 ウィンドウを閉じたときに何を復元するかは、履歴の先頭から N 件という規則で決まります。

出し方

履歴を、どこに出すか

出し場所は4つあります。結論から言うと4つとも採りますが、 それは全部を並べたいからではなく、履歴が答える問いが3つに分かれていて、 1つの窓口では届かないからです。

まとまりの粗さ

近いものほど細かく、遠いものほど粗く。境目は重ならないように順に切ります。

範囲見出し既定
今日 / 昨日日ごと開いている
今週（今日・昨日を除く）今週開いている
先週先週畳んでいる
今年の、それ以前月ごと（10月、9月…）畳んでいる
昨年以前年ごと（2024年…）畳んでいる

畳んだ束は見出しと件数の1行だけなので、5年分あってもリストは十数行で収まります。 開けばその中がまた日付順に並びます。開閉の状態は覚えません ―― 次に開いたときは既定に戻ります。

全期間を持つので、保持の上限は件数だけにします（既定 5,000 件）。 消えたファイルの行は残し、30% の文字で「見つかりません」と添えて、クリックしても開きません ―― いつ何を読んだかという記録は、ファイルが動いても価値があるからです。

4つとも採ります

A を落とすと B の「すべての履歴…」に行き先が無くなります。ライブラリで代わりを務めるには 画面ごと入れ替わってしまい、いま読んでいる文書が消えます。文書を見たまま全部を辿れる場所は A しかありません。前回の私の判断は、B と A が繋がっていることを見落としていました。

4つは競合ではなく、同じひとつの履歴に対する窓口です。答える問いが違うので、重なりません。

窓口答える問い呼び方常設で増えるインク

「窓口が4つ」は多く聞こえますが、画面に増えるのはレールの1グリフだけです。 C はキー、B は既にある文字、D は既定では出ません。実装も1つ ―― 履歴という単一のリストに、 表示の形が4つあるだけです。

B の最終行「すべての履歴…」は A を開きます。小さい窓口から大きい窓口へ、一方向に繋がるという関係で、 利用者はどこから入っても行き止まりになりません。

D は設定で切り替えます

D だけは、読んでいる面の中に文字を置きます。好みがはっきり分かれるところなので、 既存の option-cards（.claude/rules/ui-design.md）で3択にします。

設定値既定
最近読んだものを余白に表示 常に表示（全幅でも）／ パネルを畳んでいるときだけ ／ 表示しない 畳んでいるときだけ
表示する件数4 – 86

既定を「畳んでいるときだけ」にする理由は、そのときだけ左の余白が空くからです。 パネルを留めていれば A がそこにあり、痕跡は重複になります。畳めば余白が生まれ、 「戻る先が見えていてほしい」という需要がちょうど立ち上がります。

「常に表示」は全幅表示（viewport-wide）でも出します。 そのために痕跡は自分の列を持ち、本文と場所を取り合いません ―― 全幅とは 「本文が残りの幅を使い切る」という意味になります。勝手に引っ込む例外は作りません。

代わりに、選んだ結果は見たとおりです。パネルを留めたうえで全幅にして「常に表示」なら、 レール・パネル・痕跡・本文が並びます ―― それを選べる、というだけの話です。

Arto

Arto — the Art of Reading Markdown. A desktop app that renders Markdown the way GitHub does, locally and offline. Most Markdown tools are built for writing; Arto is built for reading, and the name is short for “Art of Reading”.

Markdown is where documentation, communication and thinking now live, and reading it deserves more than a preview pane. The trace keeps its own column, so full width means the text uses whatever is left rather than every last pixel.

「常に表示」＋全幅。痕跡は自分の列を保ち、本文はその右を全部使います。 引っ込む条件が無いので、設定を見なくても画面を見れば何が起きているか分かります。

原則

押しやすさと存在感は、分けて設計できます

「小さくすれば控えめになるが押しにくい」というのは、表示と当たり判定を同じものだと思っているから起きる制約です。 右側の見本は実際に動きます ―― マウスを乗せてみてください。

01
インクと当たり判定を分ける

見えているのは 16px・線幅 1.5・不透明度 30% のグリフ。当たり判定はその周囲を含む 30×30px。見た目の面積は約 1/4 ですが、押しやすさは変わりません。

乗せると 30% → 72% → 100%

02
静止時は面も枠も持たない

背景・境界線・影を一切持たず、グリフだけが浮かびます。面が出るのはホバー中の1つだけ。「ボタンの列」ではなく「小さな印の列」に見えます。

個ではなく領域で起こす

ヘッダー帯にポインタが入った時点ですべてが 72% に上がります。狙う前にもう見えているので探す必要がなく、読んでいる間はずっと 30% のままです。

残るのは日付の区切りだけ ―― 同じ面が接する唯一の場所

どの境界を、何で示すか

線・面・余白・影のうちどれか1つを割り当てます。重ねると、境界そのものが主張しはじめます。 結果として、常に引かれている線はクロームに1本もありません ―― 残るのは履歴の日付の区切りと、本文がスクロールしている間のヘッダーの下だけです。

境界これまでこれから理由
パネル ↔ 本文面 ＋ 線面のみ地の色が違うので、線は二重
レール ↔ パネル線なしパネルが出ている間は同じ面 ―― 継ぎ目は見えなくて正しい。覗きの影も右側にしか落としません
畳んだレール ↔ 本文線なし本文の余白の中に印が並ぶだけ。ぶつかるものがない
ヘッダー ↔ 本文線（常時）余白 ／ スクロール中だけ線下を何かが通るときにだけ、線に仕事がある
履歴の日付グループ—線（残す）同じ面が接する唯一の場所。ここだけは線でしか区別できない
覗いているパネル ↔ 本文—影本当に上に浮いている。影はその事実の表示
ライブラリのカード枠面16枚の枠は 16 個の矩形。面なら塊として読める
⌘K のパレット枠 ＋ 影影のみ浮いているものに枠は要らない

線を外した分、行の状態は面の段階で示します

色も枠も無くなるので、選択が弱くなりすぎないよう、行の地に段階を持たせます ―― ホバーは1段、選択中は2段。文字も 400 → 500 に上げます。ここが今回いちばん実機で確かめたい点です。

結果として、クロームから色が消えます

04 を通すと、accent 色を使う場所が UI から無くなります。残る色は本文の中だけ ―― リンク、コードのシンタックス、そしてピン留め検索の色です。あの色は利用者が自分で付けたもので、 これは意味を持つ唯一の色として残す価値があります。

目次ガターの現在地も同じ扱いにしました。青い目盛りではなく、周りが 30% の中でそこだけ 75% です。 位置は濃さと場所で分かるので、色を使う理由がありません。

開き方

パネルは3つの状態を持ちます

レールは常に見えていて、消えません。消えるのはパネルのほうだけです。 だから「開き方」は、見えているレールに対する操作として定義できます ―― 乗せれば覗け、押せば留まる。

畳んでいる

レールは地を手放し、本文の余白に印が並ぶだけ。窓のほぼ全部が本文です。既定はこの状態にしません ―― 集中したいときの状態です。

⌘B で切替

覗いている

レールにポインタが留まると、パネルが本文の上にせり出します。本文は動きません。離せば戻ります。

レールに 120ms 留まる

留めている

レールのグリフを押すと固定され、本文が押し出されます。既定の状態。同じグリフをもう一度押すと畳みます。

クリック / ⌘1–⌘3

誤爆しないための規定

  • 1開くのはレールの上だけ。窓の端 1px ではなく、40px の帯に 120ms 留まったときに開きます。通り抜けでは開きません。
  • 2閉じるのは遅らせる。パネルから出て 240ms 後に閉じます。レールからパネルへ斜めに動くとき、いったん外に出ても閉じません。
  • 3覗きは本文を動かさない。せり出しは重ね（オーバーレイ）で、影を落とします。読んでいる行が横に流れないので、誤って開いても実害がありません ―― これが「誤爆」を無害にする一番の仕掛けです。
  • 4覗きから開いたら、閉じる。覗いた状態でファイルを開くと、パネルは自動的に引っ込みます。留めているときは残ります。
  • 5esc でいつでも引っ込む。覗いている間だけ有効。留めている状態には効きません（そちらは ⌘B）。
  • 6覗きを切れる。設定に「ホバーで覗く」のオン/オフを置きます。切るとクリックと ⌘B だけになり、ホバーは完全に無効です。

テーマと幅の挙動

テーマはクリックで巡回します（Light → Dark → Auto）。今のドロップダウンは畳んで、 アイコンが現在の状態そのものになります ―― sun / moon / sun-moon の3つは既にあります。 3つを一覧したいときは右クリックでメニュー。幅は viewport-wide ⇄ viewport-narrow の2状態で、 有効中だけ一段濃く（65%）なります。

Arto

Arto — the Art of Reading Markdown. A desktop app that renders Markdown the way GitHub does, locally and offline.

Why

Most Markdown tools are built for writing. Arto is built for reading: the name is short for “Art of Reading”.

⌘K はコマンドも引き受けます。ヘッダーからテーマや幅のグリフが消えても操作が失われないのは、 すべてがここに二重化されているからです。逆に言うと、ヘッダーの3つは「よく使うものへの近道」でしかありません。

実装順

小さく確かめてから、構造に手を入れます

Phase 0 の1番は今の画面のままでも試せます。まずそこで「30% は薄すぎないか」を体で確認してから、 構造の入れ替えに進むのが安全です。

Phase 0

静かなクロームだけ先に入れる

  • --opacity-rest / --opacity-woken / --hit-size を variables.css に追加
  • 今のヘッダーのボタンをこの仕様に置き換え、サイズを 20px → 16px、線幅 1.5 に
  • disabled の戻る/進むを非表示に変更
  • 設定をタブから独立ウィンドウへ
  • 画面端のホバートリガーを外す ―― ただし廃止ではなく、Phase 1 でレール上の滞留に置き換えます。それまでの間は ⌘B とメニューだけにします
Phase 1

パネルの中身を1本にまとめる

  • root_directory をルートのリストへ。ツリーを複数ルート対応に
  • アプリ横断の閲覧履歴を持つ（Recent の実体）
  • レール（Files / Recent / Starred ＋ 歯車）と、上下2段のパネル。境界はドラッグで可変
  • タブバーと Tab の状態を外し、履歴に置き換える。「閉じる」という操作が消える
  • ウィンドウを閉じたときの復元は「履歴の先頭から N 件」に
  • 畳む / 覗く / 留める の3状態と、120ms / 240ms の滞留・猶予
  • 右サイドバーを廃止し、目次を本文右のガターへ
Phase 2

⌘K とライブラリ

  • 「開いている / 最近 / お気に入り / ルート配下 / コマンド」を1つの検索可能なリストにする
  • ⌘K のオーバーレイ（C）と、ライブラリ画面（同じリストの展開形）
  • パネルの Recent 面（A）、ヘッダーのファイル名から垂らすリスト（B）。B の最終行は A を開きます
  • 余白の痕跡（D）と、その設定（常に／畳んでいるときだけ／表示しない）
  • 起動時と ⌘T の行き先をライブラリに
  • アイコン追加 — history、folder-plus
Phase 3

落とす

  • タブバー、右サイドバー、ピン留めチップのコンポーネントと CSS を削除
  • テーマのドロップダウンを巡回クリック＋右クリックメニューに置換
  • tab.* のキーバインドとメニュー項目を整理

確認したいこと

触ってから決めたい3点

  • 130% は薄すぎませんか。このページのデモは sRGB のブラウザ表示です。実機の輝度と GitHub テーマの背景では印象が変わるので、Phase 0 で 30 / 40 / 50 を並べて決めましょう。high contrast テーマでは自動的に 1段階上げる想定です。
  • 2D の既定は「畳んでいるときだけ」で良いですか。A・B・C は入れる前提です。D だけは読んでいる面に文字が乗るので、既定を「表示しない」にする判断もあり得ます。畳んで読む頻度が高いなら、いまの既定のほうが親切です。件数の既定 6 も、実際に置いてみて決めましょう。
  • 4覗きの 120ms / 240ms は妥当ですか。短いと通り抜けで開き、長いと反応が鈍く感じます。Phase 1 で 80 / 120 / 200ms を試して決めましょう。設定で切れるようにもします。
  • 3ヘッダーの3つは、これで合っていますか。検索・幅・テーマを選びました。ここは「読んでいる最中に触るもの」だけを置く場所なので、実際の使用頻度と合わなければ入れ替えます（候補: 印刷、Finder で表示、ズーム）。
