Arto / interface — 統合案と操作子の設計

置く場所ではなく、
インクの量を減らす。

A を土台に B の ⌘K を載せ、C のライブラリを起動画面と新規タブに据える ―― その前提で、 アイコンレールをやめます。押しやすさは当たり判定が、存在感の薄さは表示の側が受け持つ、という分担に変えます。

構成 — A + B + C（起動画面） 争点 — 操作子の存在感 追加が必要なアイコン — 2 個

確定した構成

3案は、こう1つに畳まれます

案 A より 常設は左1枚

複数ルートのツリー、開いている文書、履歴、お気に入りを1本のスクロールに積みます。タブバーと右サイドバーは廃止。

案 B より ⌘K がひとつの入口

移動もコマンドも ⌘K に集約。パネルを閉じていても、これだけで全部に届きます。

案 C より ライブラリが起動画面

起動時と新規タブ（⌘T）で開く画面。お気に入りと最近読んだものが一等地に出ます。

争点

アイコンレールは、なぜ強く見えるのか

44px 幅の縦帯に 20px のアイコンが5つ、選択中は塗りつぶしのチップ。 これは「面・枠・彩度」を3つとも使っている状態で、本文と同じ強さで視野に居座ります。 しかもアイコン単体は意味を運びません ―― 星が「お気に入り」だと分かるのは、一度覚えたあとだけです。

代わりに、セクション見出しの文字そのものを操作子にします。見出しは情報としてどのみち必要なので、 操作子を置くための追加のインクがゼロになります。

原則

押しやすさと存在感は、分けて設計できます

「小さくすれば控えめになるが押しにくい」というのは、表示と当たり判定を同じものだと思っているから起きる制約です。 右側の見本は実際に動きます ―― マウスを乗せてみてください。

01
インクと当たり判定を分ける

見えているのは 16px・線幅 1.5・不透明度 30% のグリフ。当たり判定はその周囲を含む 30×30px。見た目の面積は約 1/4 ですが、押しやすさは変わりません。

乗せると 30% → 72% → 100%

02
静止時は面も枠も持たない

背景・境界線・影を一切持たず、グリフだけが浮かびます。面が出るのはホバー中の1つだけ。「ボタンの列」ではなく「小さな印の列」に見えます。

個ではなく領域で起こす

Arto

Arto — the Art of Reading Markdown. A desktop app that renders Markdown the way GitHub does, locally and offline.

Why

Most Markdown tools are built for writing. Arto is built for reading: the name is short for “Art of Reading”.

Features

GitHub-accurate rendering with the extended syntax, auto-reload when the file changes on disk, and no network required.

$ arto page README.md

読んでいるとき。ヘッダー右の3つ（検索・幅・テーマ）とパネル下の歯車が 30% で待機しています。 「進む」は履歴が無いので描かれていません。本文右のガターが目次で、青が現在地、黄がピン留め検索のヒットです。

テーマと幅の挙動

テーマはクリックで巡回します（Light → Dark → Auto）。今のドロップダウンは畳んで、 アイコンが現在の状態そのものになります ―― sun / moon / sun-moon の3つは既にあります。 3つを一覧したいときは右クリックでメニュー。幅は viewport-wide ⇄ viewport-narrow の2状態で、 有効中だけ accent 色になります。

実装順

小さく確かめてから、構造に手を入れます

Phase 0 の1番は今の画面のままでも試せます。まずそこで「30% は薄すぎないか」を体で確認してから、 構造の入れ替えに進むのが安全です。

Phase 0

静かなクロームだけ先に入れる

  • --opacity-rest / --opacity-woken / --hit-size を variables.css に追加
  • 今のヘッダーのボタンをこの仕様に置き換え、サイズを 20px → 16px、線幅 1.5 に
  • disabled の戻る/進むを非表示に変更
  • 設定をタブから独立ウィンドウへ／画面端のホバートリガーを廃止（前回の Phase 0 と同じ）
Phase 1

パネルの中身を1本にまとめる

  • root_directory をルートのリストへ。ツリーを複数ルート対応に
  • アプリ横断の閲覧履歴を持つ（Recent の実体）
  • Workspace / Open / Recent / Starred の4アコーディオン。⌘1–⌘4
  • 右サイドバーを廃止し、目次を本文右のガターへ
Phase 2

⌘K とライブラリ

  • 「開いている / 最近 / お気に入り / ルート配下 / コマンド」を1つの検索可能なリストにする
  • ⌘K のオーバーレイと、ライブラリ画面（同じリストの展開形）
  • 起動時と ⌘T の行き先をライブラリに
  • アイコン追加 — history、folder-plus
Phase 3

落とす

  • タブバー、右サイドバー、ピン留めチップのコンポーネントと CSS を削除
  • テーマのドロップダウンを巡回クリック＋右クリックメニューに置換
  • tab.* のキーバインドとメニュー項目を整理

確認したいこと

触ってから決めたい3点

  • 130% は薄すぎませんか。このページのデモは sRGB のブラウザ表示です。実機の輝度と GitHub テーマの背景では印象が変わるので、Phase 0 で 30 / 40 / 50 を並べて決めましょう。high contrast テーマでは自動的に 1段階上げる想定です。
  • 2アコーディオンは4つで足りますか。Open と Recent は性質が近いので、1つにまとめて「開いているものを上に、閉じたものを下に」並べる案もあります。3セクションのほうが見出しの行数が減ります。
  • 3ヘッダーの3つは、これで合っていますか。検索・幅・テーマを選びました。ここは「読んでいる最中に触るもの」だけを置く場所なので、実際の使用頻度と合わなければ入れ替えます（候補: 印刷、Finder で表示、ズーム）。
