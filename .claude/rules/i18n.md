# Interface Translation

Arto's own words — menus, preferences, panels, messages — are translated
with `rust-i18n`. Documents are never translated, and neither are log
messages, CLI help or `config.json` schema descriptions.

## Files

- `crates/arto/locales/<area>.<code>.yml`, compiled in by
  `rust_i18n::i18n!` in `lib.rs`. The locale is the last dot-separated part
  of the file name; files of one locale merge, so two files may add keys
  under the same top-level namespace.
- English (`*.en.yml`) is the fallback and the reference. Tests fail until
  every locale has exactly the English keys
  (`every_locale_has_the_same_keys_as_english`) and every key written in the
  source exists in English (`every_key_the_source_asks_for_is_in_english`).
- Keys follow where the string is shown, not what it says:
  `preferences.appearance.language.label`, not `interface_language`.

## Rust

- `use rust_i18n::t;` then `t!("key")`. It returns a `Cow<str>`, which
  `rsx!` cannot place, so write `{t!("key").to_string()}` for text and
  `t!("key").to_string()` for a `String` prop. Arguments use `%{name}`:
  `t!("key", name = value)`. Write the key as a string literal so the tests
  can check it; a key built at run time is not checked.
- A count goes through `crate::i18n::plural("key", count)`, which reads
  `key.one` / `key.other` with `%{count}` filled in.
- A label that a library crate (`arto-config`, `arto-keybindings`) defines
  stays English there, since the CLI and schema read it too; the app
  translates it with a `match` on the value at the place it shows it.
- A language's own name is written in itself (`English`, `日本語`) and is
  not translated, so a reader who cannot read the current language can still
  find theirs.

## Frontend

The frontend's words live in `locales/frontend.<code>.json` (JSON so that
Vite can bundle the English file). `t("frontend.…")` from
`frontend/src/i18n.ts` reads the catalog the app writes into every window's
head (`assets::main_head`) and falls back to the bundled English, which is
what a page written by `arto page` reads. `locale()` gives the locale for
`Intl` formatters.

## When the locale is chosen

Once, at launch (`i18n::init`), from `language` in `config.json` or the
system language. Native menus are built once, so a change mid-session would
leave the interface in two languages. When the chosen language would show
another locale than the running one, the Appearance pane offers a restart
(`relaunch::request`), which spawns the new instance as the old one's event
loop is torn down; the new one waits for the old process to exit before it
looks for a running instance.

Adding a language: a variant on `arto_config::Language`, match arms in
`i18n.rs` (including `native_name`), its place in `i18n::CHOICES`, and every
English locale file copied to the new code.
